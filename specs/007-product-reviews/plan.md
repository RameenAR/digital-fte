# Implementation Plan: Product Reviews & Ratings

**Branch**: `007-product-reviews` | **Date**: 2026-03-08 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/007-product-reviews/spec.md`

## Summary

Enable users to submit star ratings (1–5) and text reviews on product detail pages, with average rating displayed on product cards and detail pages. Fully client-side using React Context + localStorage — no backend required. Follows the established cart/wishlist context pattern.

---

## Implementation Phases

### Phase 1 — Types & Pure Logic (blocks all phases)

Create `types/reviews.ts` with:
- `Review` interface
- `ReviewStore` type (`{ [productId: string]: Review[] }`)
- `ReviewAction` union type
- `REVIEWS_STORAGE_KEY` constant
- `reviewsReducer(store, action): ReviewStore` — pure
- `computeProductReviews(store, productId)` — returns `{ reviews, averageRating, totalCount }`
- `validateReviewInput(input): ValidationResult` — pure, testable

### Phase 2 — RED Tests (must fail before Phase 3)

Write `tests/unit/reviews.test.ts` covering:
- `reviewsReducer`: ADD_REVIEW (new product, existing product, preserves other products), CLEAR_PRODUCT, CLEAR_ALL
- `computeProductReviews`: empty store, single review, multiple reviews (average calculation, sort order)
- `validateReviewInput`: all fields empty, name too long, body too long, rating out of range, valid input

All tests MUST fail before Phase 3 begins.

### Phase 3 — Context + Hook (depends on Phase 1)

- `context/ReviewsContext.tsx`: ReviewsProvider using useReducer + reviewsReducer; hydrates from localStorage on mount (try/catch); persists on state change via useEffect
- `hooks/useReviews.ts`: exposes `{ reviews, averageRating, totalCount, submitReview, getAverage, getCount }`
- `app/layout.tsx`: wrap children in `<ReviewsProvider>` (inside WishlistProvider)

**Checkpoint**: Unit tests GREEN after this phase.

### Phase 4 — UI Components (depends on Phase 3, can run in parallel within phase)

- `StarRating.tsx`: interactive mode (onClick per star) + display mode (read-only); uses filled/outline SVG stars; accessible (aria-label per star)
- `ReviewForm.tsx`: controlled form; inline validation errors; character counter for body; calls `submitReview` on valid submit; resets on success
- `ReviewCard.tsx`: displays reviewerName, StarRating (display), formatted date, body text
- `ReviewsSection.tsx`: composes ReviewForm + list of ReviewCards + empty state
- `RatingBadge.tsx`: compact display — average (1 decimal) + count; hidden when `totalCount === 0`

### Phase 5 — Integration (depends on Phase 4)

- `app/products/[slug]/page.tsx`: add `<ReviewsSection productId={product.id} />` below AddToCart
- `components/homepage/ProductCard.tsx`: add `<RatingBadge productId={product.id} />` inside card image area

### Phase 6 — E2E Tests + Full Validation

- `tests/e2e/reviews.spec.ts`: 10 Playwright scenarios from quickstart.md
- Run `npx vitest run tests/unit/` — all GREEN
- Run `npx tsc --noEmit` — no errors

## Key Design Decisions

1. **Context pattern**: Mirrors CartContext/WishlistContext exactly — useReducer + localStorage useEffect
2. **Reducer operates on full store**: `ReviewStore` (not per-product array) so context can serve all products
3. **`computeProductReviews` is pure**: Takes store + productId → derived data; safe to call anywhere
4. **StarRating dual mode**: Single component with `interactive` prop — avoids duplication between form and display
5. **RatingBadge reads context**: No prop drilling — reads `useReviews()` directly, consistent with WishlistToggle
6. **No new dependencies**: `crypto.randomUUID()` for IDs, built-in React for all state

---

## Risks

1. **localStorage full**: Mitigated by try/catch in context write — silent failure, no crash
2. **SSR hydration mismatch**: Mitigated by reading localStorage only in `useEffect` (client-only), not during render
3. **my-app directory in vitest scan**: Pre-existing issue — run `npx vitest run tests/unit/` with explicit path to avoid
