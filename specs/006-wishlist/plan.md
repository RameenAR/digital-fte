## Summary

Add a fully client-side wishlist feature to Lumière Parfums. Users can save products via a heart icon on product cards and the product detail page. Wishlist state persists in `localStorage` across browser sessions. A dedicated `/wishlist` page allows viewing, removing, and moving items to cart. A `WishlistBadge` in the header shows the current count. The implementation mirrors the existing `CartContext` / `useCart` pattern.

## Key Architectural Decisions

### 1. localStorage (not sessionStorage) for Wishlist
Cart uses `sessionStorage` (clears on browser close). Wishlist uses `localStorage` (persists across sessions). See `research.md → Decision 1`.

### 2. Mirror CartContext Pattern
`WishlistContext` + `useWishlist` follows the exact same `useReducer` + Context + custom hook pattern as `CartContext` + `useCart`. Consistency over novelty. See `research.md → Decision 2`.

### 3. Heart Button Inside Link (stopPropagation)
`ProductCard` is a full-card `<Link>`. The heart `<button>` uses `e.stopPropagation()` on click to prevent link navigation. Positioned `absolute top-2 right-2 z-10`. See `research.md → Decision 3`.

### 4. WishlistItem as Snapshot
Only `{ productId, slug, name, imageUrl, price, addedAt }` stored — not the full `Product`. Discontinued products still render on the wishlist page using stored data. See `research.md → Decision 4`.

### 5. moveToCart Uses Existing useCart Hook
`useWishlist.moveToCart` calls `useCart.addToCart` then `removeFromWishlist`. No circular context dependency — both contexts are consumed in the same leaf component. See `research.md → Decision 5`.

### 6. WishlistBadge Alongside CartBadge in Header
New `WishlistBadge` component mirrors `CartBadge`. Both mounted in `app/layout.tsx` nav. See `research.md → Decision 6`.

### 7. Hydration Strategy for /wishlist Page
`WishlistProvider` initialises with `[]` during SSR (localStorage unavailable server-side). Client hydrates from localStorage on mount. Brief flash of empty state on first load is acceptable and resolves in < 1 render. See `research.md → Decision 7`.
